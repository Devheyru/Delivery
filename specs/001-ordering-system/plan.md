# Implementation Plan: Minoo Delivery Ordering System

**Branch**: `001-ordering-system` | **Date**: 2026-04-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-ordering-system/spec.md`

---

## Summary

Implement the full ordering system for Minoo Delivery: an Express (single-item)
flow, a Cart (multi-vendor) flow, and an Order History dashboard — all built on
top of the existing Flutter/Riverpod/REST architecture. The core logistics engine
(delivery centers, destinations, distance) is already live; this plan fills the
remaining gaps: order submission, payment screenshot upload, and order status tracking.

---

## Technical Context

**Language/Version**: Dart (SDK ^3.7.2), Flutter stable channel
**Primary Dependencies**: flutter_riverpod, http, image_picker, permission_handler,
cached_network_image, shared_preferences
**Storage**: Remote REST API at `https://minoodelivery.com` (no local DB for orders)
**Testing**: flutter_test (widget + unit); no integration test framework in v1
**Target Platform**: Android (primary), iOS (secondary)
**Project Type**: Mobile app (Flutter)
**Performance Goals**: 60 fps UI; order submission < 5 seconds on 4G
**Constraints**: Offline ordering out of scope; screenshot max 5MB; quantity 1–10
**Scale/Scope**: Single-user session; order history paginated (20/page)

## Phase 1: Design (Complete)

See [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md).

Key decisions:
- `Order` model with `OrderType` + `OrderStatus` enums
- `OrderItem` model for line-item display in cart orders
- Unified `POST /orders` with `order_type` discriminator
- `multipart/form-data` for screenshot upload (field: `cart_tpss`)
- Cart delivery price computed server-side in v1
- `FutureProvider.family` for order history (follows existing address pattern)
- `AsyncNotifierProvider` for order submission state
